# Full Application Pages & Icon System

## Objective
Bring every remaining authenticated Aiquant page into a coherent, responsive institutional trading UI while preserving existing route contracts, API integrations, state flows, and trading safety behavior. Use React Icons and official Lineicons React components; do not use emoji glyphs as UI icons.

## Scope
- Application shell/navigation and shared design tokens.
- Dashboard, Portfolio, Live Session, History and History Result.
- Strategy Lab, Backtester, Feature Engineering, AI Predictor.
- Screener, Market Scanner, Market Intelligence, News.
- Data Management, Settings, User Profile.
- Auth and Landing page where shared visual language is relevant.

## Approach
1. Audit the current page components, props, API calls, and package manifests on the latest AI/Risk UI branch.
2. Add the official Lineicons React wrapper/free icon package and React Icons, keeping imports tree-shakeable.
3. Establish shared icon primitives and page-level visual patterns; use React Icons for broad coverage and Lineicons for selected high-signal navigation/feature icons.
4. Refine each remaining page in logical groups without replacing working business logic with fake behavior.
5. Ensure responsive layouts, semantic controls, loading/empty/error states, and consistent spacing/typography.
6. Update PAUL state/roadmap and summarize changes.

## Guardrails
- Do not change trading execution, risk authorization, backend endpoints, or credential persistence behavior as part of visual work.
- Do not present mock/demo values as live market or account data.
- Keep all existing routes and component prop contracts.
- Avoid emojis as icons.
- Verify TypeScript/build and lint if repository environment permits; report any checks that cannot be run.
